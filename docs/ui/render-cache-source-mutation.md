# Brush and resource change notifications

`IMGRenderCacheSource` is an optional interface in `MGUI.Core.UI`. Existing `IFillBrush` and `IBorderBrush` implementations need no new members. An unknown implementation draws normally and is unsupported for tracked caching. An unknown subclass of an audited mutable built-in also defaults unsupported.

A custom source must provide `VisualRevision`, `SupportsRenderCaching`, `IsRenderVolatile`, and `VisualInvalidated`. Increment the revision and fire the event after each output, support, or volatility change. The event itself also dirties dependents, even if a custom implementation omits the revision increment. Supporting caching promises deterministic, bounded, translation-safe premultiplied painting with no time, framebuffer, arbitrary screen-position, target-switching, or observation side effects. Explicit volatility always takes precedence.

Known mutable brushes and visual-state settings notify through their semantic setters. Padded, bordered, composited, uniform/docked/banded borders, texture/nine-slice resources, effect bindings, progress-gradient references, and highlight sources have dependency adapters. Shared and nested source changes forward one mutation identity across diamond paths. Copies have independent mutable brushes and notification state. Source and GPU-event subscriptions retain owners weakly; removed edges are unsubscribed when the dependency graph is reconciled. No dependency discovery, hashing, or property polling runs on idle reads.

The raw `MGCompositedFillBrush.Brushes` and `MGCompositedBorderBrush.Brushes` lists retain their public `List` types. In-place edits cannot notify automatically. After an edit, call **every consuming element's `InvalidateVisual()` before its next draw**, or invalidate the common cached brush wrapper when available. Explicit invalidation rescans the affected dependency graph, removes old subscriptions, discovers additions, and restores qualification when the final unsupported or volatile source is removed. The same rule applies to mutable backing lists exposed as read-only collections, including highlight bounds/elements.

Texture uploads (`Texture2D.SetData`), changed caller render-target contents, direct `Effect` parameter writes, and opaque callback dependencies need the same explicit invalidation before drawing. A continuously changing source should be volatile. Source tracking never disposes a caller texture, effect, brush, font, ContentManager resource, or renderer. Resource disposal immediately makes retained source-lifetime facts unusable, including during `GraphicsResource.Disposing` before MonoGame changes `IsDisposed`.

Effect-backed brushes are unsupported by default. The later cached-brush `SourceMode=ExplicitlyStatic` is a caller assertion over the whole wrapped graph; enabling caching alone is insufficient. The assertion may replace unknown/effect support rejection, while maintained volatility, known unbounded geometry, and resource lifetimes still apply. It does not make an animated or screen-position-dependent built-in safe.

Resource registration/removal and default-theme replacement notify conservatively; theme values, nested managed getters, font settings, and font-registry changes also notify. Materialized XAML resource references remain snapshots: removing and adding a resource under the same name does not rebind an existing brush to the new object. Existing copied theme values likewise remain copies. Mutate the actual consumed source or replace the owner's brush when its pixels should use a replacement. Font-resolver changes are exposed through `FontManager.FontsChanged`; caller glyph/texture edits still require explicit invalidation.

Internal consumers use `MGRenderCacheSourceDependencies`. `ReplaceSources` and explicit `Reconcile` update maintained facts without invoking the owner callback. Observable events reconcile first and then invoke the weak-owner callback with `LastNotificationStamp`; reuse that stamp for element invalidation so shared parent/child ownership advances ancestors once. `SupportsRenderCaching`, `IsRenderVolatile`, `HasUnboundedPaint`, `ResourcesAreAlive`, and `VisualRevision` are constant-time reads. Theme/resource catalogs observe nested values without treating unused defaults as actual paint eligibility contributions. Disposing the tracker removes its subscriptions and never disposes supplied resources.
