# Text and image render-cache coverage

T06 (`mgui-jpa.3.1`) follows `render-caching-design.md`. Normal Update, input, focus and layout remain live. No text/run/source graph is scanned to decide idle cache eligibility.

| Paint input | Invalidation and support |
| --- | --- |
| Text, inline formatting, bold/italic, wrapping, line padding/limits, fonts | Existing layout-affecting setters retain their layout behavior and advance paint. `SetText(value, true)` rebuilds runs/lines and advances paint without invalidating layout; equal assignments do nothing. |
| Underline, shadow, foreground, alignment, progress | Advance paint without adding layout work. Foreground state-slot edits and custom run background/underline brush notifications reach contributing ancestors through lazy source registration. |
| Parsed action or tooltip runs | `HasInteractiveTextRuns` is maintained when runs are parsed. T18 consumes it as unsupported boundary content. It is separate from time volatility. Direct Draw rebuilds bounds consumed by Update/click/tooltip logic; there is no metadata replay on a hit. Background-only brush caches can still warm while DrawSelf remains live. |
| Progressive text | Intrinsically volatile while a nonzero character rate can advance nonempty text. Completion or stopping the rate restores nonvolatile status. Public `IsRenderVolatile=false` cannot suppress intrinsic volatility. |
| TextBox selection, placeholder, count formats/visibility, line settings | Existing text/visibility components propagate paint/layout changes. Silent selection formatting now invalidates paint without invalidating measurement. Focus changes refresh selection formatting and caret eligibility. |
| Caret and password | Focused positioned caret is intrinsically volatile, including the blink-hidden phase; position/color/blink-rate/entry-mode changes invalidate paint. Unfocus restores nonvolatile status. PasswordBox inherits caret behavior and existing mask glyph layout semantics. Current PasswordBox has no temporary reveal feature. |
| Image source/key/source rectangle/render size/opacity | Effective source replacement notifies and invalidates; same-size changes only advance paint, changed render size retains layout invalidation. Named-resource notifications compare the event resource key. Catalog and image/layout changes share one scoped mutation stamp; nested public callbacks retain distinct changes and restore the previous scope. Textures stay caller-owned. |
| Image tint/state tints, sampler | Paint-only invalidation, equal assignments are no-ops. Visual-state transitions remain covered by base state invalidation. |
| Image effects/configuration/standard or constant parameters | Tracked effect binding notifies the owner once. Effect or ConfigureEffect disqualifies a boundary; clearing both restores source support. External effect parameter writes require explicit invalidation and do not grant support. |
| Inline images | Lazy keyed-source adapter observes resource replacement and the current texture's lifetime. Replacing/removing a key releases old texture dependencies; disposal of the current texture rejects capture. |
| Fonts/theme/inherited colors/UI scale | Existing desktop resolver/engine/scale and inherited-context paths invalidate real text elements; resolved font metrics retain layout invalidation. Authored font family/size values keep their existing semantics. External custom text-engine state and texture uploads require explicit invalidation before drawing; metric changes also require the existing layout invalidation API. |

`Runs`, `Lines`, and run settings are already read-only at their public boundaries. The current inline parser creates only immutable solid/gradient color brushes. Custom run data can contain mutable brush graphs. Raw nested `MGCompositedFillBrush.Brushes` edits require `element.InvalidateVisual()` before drawing; this refreshes observed run dependencies and lines without layout work. Tests install custom public run data through reflection solely to exercise that otherwise inaccessible graph, without introducing a runtime API.

Opaque texture uploads require explicit owner invalidation before the next Draw. Continuously updated texture owners should set `IsRenderVolatile`. Explicit invalidation refreshes a named image's effective source without requesting layout; a raw dictionary edit that changes metrics also needs explicit layout invalidation. Observable source setter changes handle dimensions automatically.

Native verification uses `MGUI.RenderCacheTestHost --text-images` through `tools/render-cache/test-native.py`: owned Xvfb, serialized graphics lock, DesktopGL Release, Mesa llvmpipe software renderer. Checks use RGBA readback, actual mouse press/release command dispatch, repeated tooltip resolution, cache-hit counters, exact one-generation/no-layout source propagation, source lifetime/support restoration, no-op notifications and idle stability. Software rendering provides correctness evidence, not hardware performance claims.
