# Explicit content render-cache boundary

`MGUI.Core.UI.Containers.MGRenderCache` derives from `MGSingleContentHost` and accepts `MGWindow` in its constructor. `IsCacheEnabled` defaults to true only on this explicitly chosen wrapper. Ordinary hosts remain unchanged. Set content through the existing `SetContent` APIs; measurement, layout, ownership, namescopes, hit testing, focus and update traversal use the ordinary single-content-host implementation. `MGElementType.RenderCache` is appended, preserving existing enum values. The default theme supplies no background, like ContentPresenter. XAML integration is a separate task.

Only `DrawContents` is replaced. Background, self, all component stages, overlay and wrapper public callbacks keep their normal positions. Call inherited `InvalidateVisual()` after opaque custom state changes; existing public revision values and `desktop.RenderCaches.Statistics` provide diagnostics. No extra public debug protocol is introduced.

After normal desktop Update, call `desktop.PrepareRenderCaches()` before clearing or drawing the world. The first qualifying final content draw records the actual generation; a later preparation captures it. A warm hit composites one texture without descendant painting, discovery or bookkeeping replay. Omitting Prepare or changing content after Prepare draws current content directly. Preparation uses the existing manager and operation service; final Draw never allocates targets or switches targets. Capture paints original Content directly, with nested cache lookup and observation mutation suppressed.

Only the exact runtime MGRenderCache type uses its own Content-only operation. Derived wrappers may override child enumeration or content painting, so they retain ordinary traversal with no cache request even when IsCacheEnabled is true. An explicit SupportsRenderCaching override on such a subtype may qualify its full audited painting as a descendant of a separate enclosing boundary; it does not assert that its own virtual traversal is identical to Content.Draw. No subtype traversal is silently rewritten.

Admission reads the content's maintained eligibility snapshot plus relevant wrapper state. Positive geometry is required on both wrapper and content; a visible zero-size child inside a full-size wrapper remains empty. Owner/content visibility, owner clipping, layout, user/intrinsic volatility and the original operation's exact opacity, transform, clip, settings, attachment and generation checks apply. Wrapper decoration/hook support is not incorrectly included in the captured subtree. Unknown custom participants still require the protected support contract. This increment does not broaden supported drawing contexts.

## Direct-draw observations

A boundary registers a weak observer with each distinct element reachable through its retained content paint edges when it first obtains a qualifying observation. Registration is change-time work. Ordinary elements without observers have a null-check path; warm boundary draws do not walk ancestors or descendants. An ordinary contributing descendant Draw entry invalidates the enclosing observation before bookkeeping changes, even if that draw exits early. The boundary's own direct content traversal temporarily suppresses only its own observer, allowing it to record the complete direct generation. Wrapper hooks that draw a descendant before or after that content traversal are not suppressed.

A small entry/finally seam around the existing MGElement draw body detects skipped or failed boundary content stages. Each invocation saves and restores its own content-completion marker, so a nested draw in begin/ending/end hooks cannot acknowledge the outer invocation; exception exits also reject reuse. An alternate partial-clipped child draw, fully clipped boundary draw, or late wrapper hook therefore cannot leave prior clipping bookkeeping reusable. Preparation sends no notifications and writes no live clipping flags. Actual semantic revisions remain separate: drawing does not pretend to be a visual mutation.

Removed paint branches clear nested boundary observations during the existing change-time context invalidation traversal, including inactive branches that retain logical Parent links. Structure changes remove old publisher registrations; later qualified direct drawing registers current retained edges. Hidden/empty/disabled content, managed detach and raw root removal clear publishers and invalidate entries. Root membership is reconciled by the existing desktop lifecycle. Publishers hold weak references, so live publishers cannot retain abandoned boundaries. New registrations and normal notifications prune dead slots. Targets retire logically immediately and are disposed at the existing safe preparation/lifecycle points.

## Validation

`MGRenderContentObservationTests` covers distinct retained-edge registration, membership cleanup, independent observers, allocation-free repeated registration checks, and 24 weak-owner cohorts with a live CPU publisher. Those synthetic CPU graphs isolate registration lifetime from existing ordinary constructor/input retention; they do not fabricate a GraphicsDevice or claim graphics correctness.

`ContentBoundaryNativeTests` runs `MGUI.RenderCacheTestHost --content-boundary` through the owned-Xvfb helper. Seventeen named groups cover exact full-frame direct/cached RGBA, a built-in text/rectangle panel, moving-world sentinels and zero final target switches; first observations; warm paint/update/input-eligibility counters; no idle child discovery/builds/allocations; omitted preparation and late mutations; alternate descendant and skipped boundary draws; wrapper and descendant callback behavior, reentrant begin/ending/end hook and exception recovery, and default/explicitly-supported derived repeated-child traversal fallback; disabled/empty/hidden and zero-geometry lifecycle; root/managed detach and inactive nested paint-branch cleanup while logical Parent survives; volatility/opacity fallback; nesting; twenty replacement cycles; and desktop disposal. Direct/cached PNG pairs and JSON checks/statistics are retained under the reported `/tmp/mgui-content-boundary-*` artifact directory. Full composition/settings/alpha matrices remain the downstream T16 lane.

```sh
flock --close /tmp/mgui-render-cache-dotnet.lock dotnet test MGUI.Tests/MGUI.Tests.csproj -c Release --nologo --filter 'FullyQualifiedName~ContentBoundaryNativeTests|FullyQualifiedName~MGRenderContentObservationTests' --logger 'console;verbosity=minimal'
```

Native evidence uses MonoGame DesktopGL Release and the helper's private Xvfb/graphics lock, with Mesa llvmpipe software rendering. It establishes correctness, not hardware frame-rate performance. No cache path skips update or input observation work.
