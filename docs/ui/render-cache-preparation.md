# Preparing render caches

Hosts opting into cached producers call `desktop.Update()`, then `desktop.PrepareRenderCaches()`, then clear/draw their world and call either desktop Draw overload. Preparation is optional: omitting it forces direct rendering even when an old target is ready. The first preparation attempt after a completed Update processes existing observations; subsequent calls with that Update token do nothing. New work waits for the next Update/Prepare pair. No producer is enabled by adding the preparation call alone.

Preparation must run outside **all** SpriteBatch, PrimitiveBatch and DrawTransaction sessions, before anything valuable is drawn into the backbuffer. MGUI tracks active DrawTransaction lifetimes, including deferred transactions and transactions on another renderer sharing the device, and bypasses misuse without ending caller batches. Raw external batch begun state is not publicly queryable; that part is a mandatory host precondition. Reentrant Prepare is a no-op.

Bound host targets, including multiple render targets, bypass preparation without switching or modifying them. Local MonoGame `GraphicsDevice.ApplyRenderTargets` resets viewport/scissor and clears DiscardContents targets on rebinding; restoring bindings would not recover scene pixels. The coordinator therefore never inserts capture into final Draw. A caller can render UI directly onto host targets without preparing caches there.

Each capture explicitly applies canonical blend/rasterizer/depth/sampler state before any painting, including primitive-first sources (PrimitiveBatch.Begin does not apply DrawSettings). It uses an independent transaction, flushes it, unbinds its candidate, restores public device state, validates the observed generation again, and only then publishes. Clear/Dispose during capture cancel publication and defer destruction until unbinding. Producer exceptions propagate after cleanup; native target construction/first-bind failures record the manager diagnostic and fall back to direct painting. Publicly restorable state includes viewport, scissor, rasterizer/blend/depth states, blend factor, index buffer, all exposed texture and sampler slots (pixel and vertex). MonoGame exposes neither the bound shader/effect program nor current vertex-buffer bindings through public getters in this dependency: the host must bind its own vertex buffers and apply its own effect pass for subsequent scene draws. Caller effects and transaction settings are not modified. No reflection or fabricated Effect getter is used.

## Internal producer contract

`MGRenderCacheOperation` is a stable per-owner/per-paint-site identity, weakly held by the resource service. The producer calls `TryDraw` at its original painter position. On every miss or ineligible invocation it calls `BeginDirect`, paints directly, and calls `CompleteDirect` only on success. BeginDirect invalidates the preceding observation even for partial clips, opacity changes or disabled caching. During capture both observation mutation and nested lookup are disabled. Weak invalidation forwarding retires semantic/root detach changes without rooting producers in event publishers.

`IsSourceCurrent` must check maintained source revision, support, volatility, lifetimes and eligibility in constant time. It must reject public callbacks, unsupported/custom participants, unbounded paint and unresolved layout as required by the architecture contract. This foundation deliberately does not discover or bless a subtree. The later brush and panel producers own their maintained source/eligibility registrations. A custom internal producer that declares unsafe drawing eligible violates this contract.

The base operation validates owner revision epoch/categories, observation generation, attachment identity, full bounds/offset, effective opacity, visual state, source/context token, viewport and backbuffer dimensions. Only canonical full-backbuffer viewports, integer translation, opacity 1 and canonical Deferred/AlphaBlend/PointClamp/no-effect/scissor/depth-none settings qualify. Producers advance the supplied context token for additional relevant state. A direct observation is required after any invalidation; neither Update nor Prepare can invent one. Revision overflow advances the shared epoch before restarting the observation sequence.

Capture receives the same logical bounds and DA.Offset, with current renderer clock. The independent transaction transforms those coordinates into the target. Explicit screen-space scissors use `DrawTransaction.MapScreenClip`; ScrollViewer and RatingControl are adapted. MGElement capture paths suppress public callbacks and RecentDrawWasClipped writes. Input-consuming text action/tooltip dictionaries and other side-effectful controls remain ineligible until their producer classification explicitly handles them. No layout or input pass runs during preparation.

## Native verification

Build current source with the shared dotnet lock, then run `python3 tools/render-cache/test-native.py MGUI.RenderCacheTestHost/bin/Release/net8.0/MGUI.RenderCacheTestHost.dll --preparation`. The helper owns the graphics lock and private Xvfb; never hold an outer graphics lock. The xUnit `RenderCachePreparationNativeTests` wrapper uses the same helper. The dedicated producer compares exact backbuffer RGBA pixels against direct rendering with a moving world, primitive-first painting under poisoned host state, explicit scissors, misses and warm hits; it also exercises omitted/duplicate preparation, stale generations, capture exceptions/reentrancy/Clear/Dispose, viewport changes, external transactions and single/multiple bound host targets. The accepted benchmark fixture and retained baseline artifacts are unchanged. Software-renderer results establish correctness, not hardware FPS.

A content-boundary producer must additionally invalidate observations when any ordinary direct descendant draw can change its captured bookkeeping, using maintained paint ownership rather than an idle ancestor/tree scan. It must arrange that invalidation at its draw entry even when its content paint site is skipped. The generic paint-site operation does not infer those boundary-specific relationships. Brush producers leave the owner's ordinary draw/input bookkeeping live.
