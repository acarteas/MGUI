# Decoration and live-layer render tracking

T31 (`mgui-jpa.3.5`) audits the complete container, decoration, menu, overlay and window inventory in `render-caching-design.md`. This is setter/source coverage for the later exact-type eligibility policy, not an automatic opt-in or a blanket promise that subclasses qualify. Unknown custom elements remain unsupported. Layout, input and normal updates run independently of cached painting.

## Maintained eligibility inputs

`MGElement.ControlRenderFacts.cs` exposes two internal constant-time facts for T18:

- `ControlPublicDrawCallbackCount`: zero by default; `MGUniformGrid` maintains its `OnRenderCell` multicast invocation count at add/remove time. Removal of a missing handler is a no-op. Normal draws invoke every remaining subscription at the original cell-paint location; capture invokes none. An enclosing boundary must bypass whenever this count is nonzero.
- `HasUnsupportedControlRenderState`: false by default; `MGContextMenuItem` reports nonnull `ComputeIsVisible`, external-host `MGResizeGrip` reports its external paint ownership, and `MGOverlayHost` always reports its cross-owner public painter. Relevant setter/ownership changes invalidate immediately so aggregate eligibility can recover after removal. No delegate inspection or child traversal occurs when reading these facts.

These facts supplement public base draw-hook counts, intrinsic volatility, source support, clip and transform facts. They do not replace them. A false local fact cannot override an unsupported child or resource. T18 must aggregate contributing paint children, never logical popup parent links.

## Observable resources and opaque changes

Control source enumeration is lazy: ordinary construction/painting does not instantiate dependency observers. First cache/revision observation registers inputs; replacement and explicit `InvalidateVisual()` rediscover the affected graph. T08 adapters maintain brush/theme/state-source notifications, volatility, support and lifetime. Raw public lists, texture uploads and arbitrary external delegate state still require explicit invalidation or ordinary live rendering, as specified in the main design. A custom brush or generated custom control does not become supported because it appears inside an audited container.

No T31 change adds an idle subtree walk, property hash, delegate polling, automatic target or new layout pass for a pure visual setter. Unsupported families retain ordinary painter order and update/input behavior.
