# Cached fill brushes

`MGUI.Core.UI.Brushes.Fill_Brushes.MGCachedFillBrush` wraps one non-null `IFillBrush`. Caching is enabled by default on this explicit wrapper; ordinary brushes stay unchanged. `Copy()` copies the inner brush into an independent wrapper. Each wrapper creates its own cache registrations and operations when consumed, while the same element and paint site may consume both; ready targets are not copied. The copied inner source follows that source brush's `Copy()` contract; textures and effects may still be shared. After an opaque mutation to a shared GPU resource, invalidate each wrapper that consumes it.

Use the wrapper at one of the three stable built-in element paint sites: `BackgroundUnderlay`, `BackgroundOverlay` or `OverlayBrush`. These sites retain independent identities, including two sites on one owner and one shared wrapper consumed by several owners. A direct call to `MGCachedFillBrush.Draw`, or a wrapper nested inside another brush without a stable paint-site identity, draws the source normally. An outer cached wrapper may still wrap an arbitrary eligible nested source graph.

`SourceMode` defaults to `MGRenderCacheSourceMode.Tracked`. Known brush adapters and custom [`MGUI.Core.UI.IMGRenderCacheSource`](../../MGUI.Core/UI/Rendering/MGRenderCacheSourceDependencies.cs) sources provide change-time dependency observations. Unknown sources and effect-backed sources are unsupported in tracked mode. `SourceMode=ExplicitlyStatic` asserts that the complete source graph emits bounded, premultiplied, local/UV-only pixels without time, screen-position, interaction, untracked mutable dependencies, side effects or target switches. It can admit a caller-audited static effect/custom source, but never overrides known volatility, disposed resources, cycles or known out-of-bounds painting.

Observable source changes and `Brush`, `IsCacheEnabled` and `SourceMode` replacements invalidate registered owner/site observations automatically. Call `cachedBrush.InvalidateVisual()` before drawing after opaque effect parameter writes, texture uploads, caller render-target changes or raw list edits. In-place edits to public composited brush lists are not observed. For a raw brush that is not wrapped by `MGCachedFillBrush`, call `MGElement.InvalidateVisual()` on every consuming element. These notifications invalidate pixels without forcing layout.

Call `desktop.PrepareRenderCaches()` after the normal desktop update and before clearing or drawing the host scene. First use paints the inner brush normally and records its exact bounds, offset, visual state and owner revisions. A later preparation captures that observation; final composition only reads a valid texture. Omitting preparation, changing a generation, detaching an owner or encountering an unsupported context paints the original source with unchanged arguments. The wrapper never owns or disposes caller textures/effects.

Fractional incoming opacity, partial inherited clipping, nonstandard blend/sampler/depth/sort/rasterizer state, any effect supplied through the incoming `DrawSettings.Effect`, and unsupported transforms bypass in every source mode. An effect inside the wrapped brush graph is a separate case: it remains unsupported in `Tracked`, but may be used with `ExplicitlyStatic` when the caller audits and asserts the complete source graph. Original per-layer alpha is preserved. Integer translation and resolved layout UI scale remain eligible when the other context checks pass. `MGElement.IsRenderVolatile` disables reuse without changing update, input or layout; intrinsic running-control volatility cannot be suppressed by setting this flag false. Cached backgrounds do not require the owner's unrelated content painting to be eligible.

For the complete contract and XAML usage, see the [render caching guide](render-caching.md). The [native background-parity lane](render-caching-background-parity.md) covers layered fills, effect and state fallbacks, invalidation and resource lifetimes. Its software renderer establishes graphics correctness, not hardware FPS.

The [matched comparison](render-caching-comparison.md) found 36 small cached fill sites slower than normal rendering in every tested synthetic configuration. This does not establish the cost or benefit of one application's expensive fill; measure the target workload with preparation included.

The weak-owner lifetime fixtures use synthetic CPU owners while retaining a real desktop/device/root attachment. They isolate cache registration from unrelated element ownership and do not prove that ordinary removed windows or children are collectible. Separate native coverage checks inactive contextual content with retained logical parent links. See the [cache lifetime notes](render-caching-lifetime.md) for that boundary.
