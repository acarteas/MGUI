# Selective render caching contract

Status: architecture contract for mgui-jpa.1.2, pending independent architecture review; source audited 2026-10-17. Coordinator accepted the native mgui-jpa.1.1 baseline after direct review; its measurements and explicit downstream gates are recorded below.

This is the implementation contract for explicit cached fill brushes and a single-content cache boundary. Ordinary rendering remains the default. An application places animated content in ordinary sibling elements, in its intended painter order. There is no automatic bitmap per widget, retained-command renderer, reduced update frequency, or input/layout shortcut.

The snippets describe members, not a requirement to convert existing classes to partial declarations. Revision properties have private/internal setters and begin at 1. They are observable diagnostic values, not frame clocks. The resource interface is optional and does not alter the legacy brush interfaces. Implementing it asserts bounded, deterministic, translation-safe premultiplied painting as described below; its event must fire for revision, volatility or support changes. Unknown resources without this contract bypass. A custom element must explicitly override `SupportsRenderCaching` to true and meet the same contract; inherited built-in support never silently blesses a subclass. The default getter uses an exact runtime-type allowlist (including known generic definitions) of audited built-ins. A new subclass defaults false. The getter must be constant-time and must not walk children.

XAML types: `MGUI.Core.UI.XAML.RenderCache : SingleContentHost`, with nullable `bool? IsCacheEnabled`; `CachedFillBrush` has one required `Brush` property, nullable `bool? IsCacheEnabled` and nullable `MGRenderCacheSourceMode? SourceMode`. `Element.IsRenderVolatile` is nullable bool and applies to the runtime flag. Unspecified XAML values leave runtime defaults. Add `MGElementType.RenderCache` at the end without renumbering existing values. Existing SingleContentHost content-element syntax and brush nested-property syntax apply. An empty RenderCache is valid and allocates nothing; a CachedFillBrush without Brush fails parsing with a property-specific error. Copy makes a new wrapper around `Brush.Copy()`, copies IsCacheEnabled and SourceMode, and shares neither request identity nor targets. Null constructor/setter values throw ArgumentNullException; equal assignments are no-ops. Undefined SourceMode enum values throw ArgumentOutOfRangeException; changing mode invalidates all registered owners and reconciles support before another hit.

Manager negative budget/entry settings and nonpositive MaximumTargetDimension throw ArgumentOutOfRangeException. Zero disables allocation and immediately clears retained entries. Budget/dimension setters, Clear and explicit disposal must be called on the UI/render thread outside final draw transactions. Budget/dimension changes during Prepare throw InvalidOperationException. Reductions drain retired targets and evict immediately to both limits at that safe point. Clear disposes cache-owned GPU resources, drops pending requests, advances service generation and leaves future caching enabled. Dispose is idempotent, clears and permanently disables this service. Clear/Dispose invoked reentrantly during Prepare cancel the current generation immediately and defer destruction of the currently bound candidate until its transaction is ended and the target is unbound in finally; no candidate can then publish. RetainedBytes and EntryCount include that candidate until disposal. `DisposeRenderCaches()` delegates to it; subsequent Prepare calls are no-ops, cached owners draw directly, and accessing RenderCaches returns the same disposed service. There is no lazy resurrection. Hosts call DisposeRenderCaches before abandoning a desktop or disposing its renderer/device. Existing applications using no caching need not add lifecycle code to remain correct.

## Revisions and change propagation

All mutation, Update, preparation, composition and disposal run on the host's UI/render thread. Cross-thread mutation remains unsupported. A semantic visual change advances VisualRevision; a layout-affecting change advances LayoutRevision and VisualRevision; membership/order/paint ownership changes advance StructureRevision and VisualRevision. Values are monotonic within a service generation. On impending ulong overflow, invalidate all entries and restart revision counters in a new service generation before publication; never allow wraparound to match an old key.

Each element's revisions summarize its own paint and contributing descendants, not just local setters. Advance affected ancestors through a maintained paint-ownership graph. Use a mutation stamp to avoid double propagation when an element is reachable through component and content notifications; duplicate aliases are not duplicate painted children. GetChildren/Components and control-specific active content establish paint edges. `Parent`, `ComponentParent`, `ManagedParent` changes trigger reconciliation, not three unconditional parent walks. For ListView the data grid reaches the owner through its actual DockPanel/ScrollViewer path; the ManagedParent shortcut must not increment the owner twice. ToolTip/ContextMenu Parent links, separately drawn nested windows and inactive content are not flattened paint edges. Activation/switching changes structure before next composition. Internal subscriptions must detach on removal, replacement, Reset and reparenting, including old and new ancestors; preserve old collection membership to handle Reset.

Maintain counts for unsupported participants, volatile participants, public draw hooks, unsupported transforms, unbounded paint, and unresolved layout; maintain captured paint bounds and resource dependency registrations. Registration and relevant changes can inspect the affected subtree/resource graph. Idle eligibility is a constant number of counters and key comparisons per boundary/brush invocation. No idle tree traversal, recursive content hash, brush-list hash or whole-tree property polling is permitted. Dirty propagation may be O(depth), structural reconciliation O(changed subtree), and layout retains its existing cost. Removing the last volatile/unsupported child must restore eligibility; counts cannot be one-way flags.

`InvalidateVisual()` marks the receiver and painted ancestors dirty immediately, even in initialization/deferred-event scopes. It also schedules dependency/eligibility reconciliation for that receiver's contributing resource graph and subtree before any later request can qualify. This intentionally supports explicit notification after an unobservable raw-list mutation. It does not invoke LayoutChanged, clear measurement caches, force UpdateLayout or queue a window layout refresh. An initialization scope can coalesce propagation, but it must synchronously make old cache generations unusable. Layout invalidation hooks must run before `LayoutChanged`'s existing deferral early return; actual geometry changes and layout completion update revision/counters without introducing new layout passes.

Do not invalidate from all PropertyChanged notifications. Patch semantic setters, collection/control events and existing visual-state transitions deliberately. Ignore bookkeeping `RecentDrawWasClipped`, `ActualLayoutBounds` writes that merely repeat current geometry, `IsLayoutValid` notification churn, derived display properties, names, metadata, input handler subscription, and unchanged assignments. A changed ActualLayoutBounds/effective clip context may disqualify a key but must not force layout. Inherited foreground/scale/theme/resource changes invalidate affected dependents at change time; update propagation must account for derived enabled/selected/hover/pressed states. A binding invalidates through the setter it invokes, not by a second blanket subscription.

## Ownership, budgets and device lifetime

The desktop owns one CPU-only manager from construction; no RenderTarget2D exists until an eligible queued request is prepared. Entries are per desktop/device, weak owner identity, operation identity and generation. The service must not strongly root an element, cached brush, window or abandoned desktop from a GraphicsDevice event. Resource subscriptions held by an active owner are detached when its paint registration is removed; device events use a small weak-reference forwarding object that never closes over the manager/desktop. Dispose explicitly unsubscribes the forwarder. A dead weak target self-unsubscribes on the next event. Device disposal also releases its GPU resources, but deterministic desktop cleanup remains the host's responsibility.

Owner registration and request validity are removed immediately on observable managed tree detach and on disabling a wrapper/brush. MGDesktop.Windows remains a public List<MGWindow>; raw Remove/Clear/reorder cannot be observed synchronously. Reconcile its identity membership once at entry to each desktop Update, PrepareRenderCaches and Draw, reusing existing window enumeration where possible, against the prior root-membership set. This is O(top-level windows), not a subtree eligibility traversal. Removal invalidates pending/ready registrations before any preparation/composition in that lifecycle call; reinsertion establishes a new attachment generation and requires a new direct observation. Include OverlayWindow and currently active popup roots through their explicit setters, and nested/modal attachment through MGWindow AddNestedWindow/RemoveNestedWindow/ModalWindow changes. A root removed and reinserted entirely between lifecycle calls without any intervening painting is observationally unchanged; it cannot cause stale work to be published for a different observed state. Call Clear at a safe point for synchronous GPU release after raw root-list edits if needed. Mark its targets retired; dispose them at the next safe Prepare, Clear or Dispose, never while a final external DrawTransaction may still have a deferred sprite referencing them. Retired targets still count against both budgets and cannot be used for a hit. This distinction between immediate logical release and safe GPU disposal applies to replacement and eviction too; eviction/allocation occurs only at safe preparation or explicit manager lifecycle calls. Entries for direct, unmanaged calls hold weak owner/brush identities and are swept during Prepare; retain at most the configured limits if an owner disappears without a detach notification. A shared resource subscription uses weak owner references; dead listeners are pruned. No global owner registry may retain desktops. Reparenting invalidates both former and new ancestor boundaries. Cross-desktop reparenting requires a normally valid MGUI ownership change; caching does not relax MGElement's fixed ParentWindow constraints.

Use `RenderTarget2D` with SurfaceFormat.Color (RGBA8), no mipmaps, DepthFormat.None, multisample count zero, RenderTargetUsage.DiscardContents. Charge checked `width * height * 4` physical bytes per allocated target, including in-flight preparation. No pool or oversized target reuse in this increment. RetainedBytes and EntryCount report every allocated, not-yet-disposed manager target, including retired and in-flight targets; pending CPU requests are not entries. Keep at most MaximumEntries pending operation snapshots, coalesce by owner/operation with the newest observation, process in insertion order, and decline additional distinct requests when full (they draw normally and may retry next frame). Zero budget/entries also clears pending requests. Width and height must be positive and no greater than MaximumTargetDimension, and allocation must satisfy both budgets before construction. The default dimension cap of 4096 is a manager allocation policy, not a claim about hardware capability. MonoGame DesktopGL stores its GL_MAX_TEXTURE_SIZE result in internal GraphicsDevice._maxTextureSize and exposes no public maximum in this dependency version; do not use reflection or change MonoGame. Native RenderTarget2D creation and first binding/clear are the authoritative device-limit/format validation. Catch allocation/binding failures, dispose any constructed candidate and restore state, record the exact diagnostic, and use direct rendering. No smaller-size retry or allocation loop is permitted. If a later supported backend exposes a public dimension limit, additionally reject dimensions above that limit before allocation. Evict least-recently-composited entries first, break ties by creation sequence; replace/dispose an invalid owner's old target before allocating its replacement so transient bytes and entries also remain bounded. Candidate larger than either limit is never allocated. Failed allocations are suppressed until its size/device/budget/dimension-policy generation changes. A dimension-cap change advances policy generation and immediately evicts entries above the new cap. No stale target is a fallback.

DeviceResetting and DeviceReset discard pending/prepared generations and owned targets. Device Disposing permanently disables the manager. Device identity, reset generation, viewport/backbuffer dimensions and budget changes invalidate relevant requests. Validate resources are not disposed before use. Never dispose caller textures, effects, fonts, brushes or renderer. Resource tests must count allocations/disposals and use WeakReference collection checks with a live device to expose event roots.

## Exact frame protocol and stale-generation rules

1. Host updates normal renderer/input state and calls `desktop.Update()`. Each completed desktop Update advances a logical frame token. Cached painting never skips Update, bindings, layout, caret/timer updates, focus or observation work.
2. Host calls `desktop.PrepareRenderCaches()` after Update, before any scene rendering/clearing and outside all SpriteBatch/PrimitiveBatch/DrawTransaction sessions. This is the only cache preparation phase. The call is optional.
3. Host draws/clears its scene, then calls either normal desktop.Draw overload. Final UI composition may read targets and queue CPU requests; it never allocates a target or switches render targets.
4. A miss/ineligible/stale/late-changed owner draws normally in its original painter position. Only an eligible, successfully completed normal final Draw can queue a request for the exact generation and draw context it just observed. No proactive first-frame capture from Update. A request is prepared at a later safe phase only if every field still matches.

Prepare is idempotent per logical frame token: the first call processes the then-pending eligible queue, later calls do nothing even if new requests arrive. A Draw with no successful Prepare in that frame uses normal rendering, including when a valid texture survived from an earlier frame. This makes omission always correct and ensures hosts cannot accidentally use an unmanaged preparation cadence. Multiple Draw calls after the same Prepare may hit only if the full key still agrees; custom draw settings/opacity/offset changes miss. Hosts that draw without another Update keep the same logical token; newly queued work waits for the next Update/Prepare pair.

The caller guarantees nothing valuable has been drawn into the active target/backbuffer before Prepare. Saving and rebinding a DiscardContents target does not preserve its pixels. If non-backbuffer render targets are bound on entry, Prepare performs no captures and records the unsupported-call-context reason; it does not attempt to save/restore their contents. Preserve GraphicsDevice viewport, scissor, bindings and graphics state in try/finally; use independent completed transactions for capture. No active external transaction can safely be inferred from device state, so the host precondition is mandatory and documented in the sample. Never auto-call Prepare from desktop.Draw.

Each pending request contains weak owner/operation IDs, service/device generation, observed visual/layout/structure revisions, resource revision token, bounds/origin/offset, visual state, effective opacity, transform/settings/clip eligibility and layout-resolution token. Copy this immutable snapshot at the end of direct Draw only if no semantic mutation occurred during that Draw. A capture consumes the snapshot, never clears an owner's dirty flag unconditionally. Before allocation, immediately before painting and after painting, validate snapshot equality, attachment, source lifetimes and eligibility. Any mutation during preparation rejects publication, disposes the candidate, and leaves the new generation dirty; it must first be observed by a later direct Draw before it can queue. Nested invalidation, property callbacks, resource events and reentrant Clear/Dispose therefore cannot make stale pixels current. Reentrant Prepare is a no-op; a reentrant Draw during capture bypasses all cache lookup/request generation.

Every ordinary direct Draw that can touch a boundary's contributing descendant bookkeeping invalidates its previous observation record before drawing, whether or not it is eligible to queue a request. On successful completion replace the record with the actual draw context; an ineligible/partial-clipped/opacity/preview draw leaves it non-reusable. A previously Ready texture is not sufficient proof. In particular, a window main draw followed by its offset, 0.25-opacity drag preview must force the next main draw through the direct path before warm reuse; descendant flags last describe the preview. Nested direct draws invalidate every affected enclosing observation through maintained paint ownership, without scanning for ancestors.

A warm entry is usable only when its generation/key equals current maintained state AND its observed-generation record is still valid AND Prepare ran this frame. A future revision is never considered equivalent merely because dimensions stayed equal. Entries have internal states `Pending`, `Preparing`, `Ready`, `Rejected`; owner absence is no entry, and invalidation makes Ready immediately unusable. Rejected means direct fallback until a new successful direct observation; no negative caching of eligibility after the cause changes.

## Capture geometry, painting and input invariants

MGRenderCache overrides only its content painting stage. Its own background, components, overlay, and callbacks keep their normal positions in MGElement.Draw. Capture its Content subtree into the wrapper's LayoutBounds, using the clipping already implied by wrapper ClipToBounds. Wrapper padding/alignment/measurement and SetContent behavior follow MGContentPresenter. No offscreen measurements or extra layouts are introduced. Content replacement changes structure; an empty/hidden/collapsed/zero-size boundary issues no request and immediately releases its target. A hidden descendant is included in change tracking but paints nothing; hiding/showing it invalidates. Fully clipped boundaries draw through the existing normal early exit and do not request resources.

MGCachedFillBrush captures only its inner brush's supplied Bounds. Keep underlay, fill overlay, self/border and overlay passes separate. A shared brush can be called by two elements, or twice by one element at different paint sites; operation identity includes wrapper identity and a stable paint-site token assigned by built-in paint sites. Do not use only brush identity or dimensions. Custom direct callers without a stable site token conservatively bypass the brush cache. Include full bounds and absolute origin/DA.Offset/VisualState, not only size: some brushes depend on owner state and position. A change of integer position/scroll offset is a miss even if translation reuse could later be optimized.

Capture uses a target-local translation of the same logical coordinates, never a mutation of element layout/origin or DA.Offset visible to control logic. All pixel-scissor operations must map screen coordinates through the capture context; specifically adapt MGScrollViewer.DrawContents and other explicit screen-scissor paths, not just GetDrawTargetBounds. Target-local clip is intersected with target bounds. A maintained supported-paint bound contains all pixels; negative padding/outside-bounds brushes cannot qualify as fill-brush captures unless the whole brush is demonstrably confined to supplied Bounds. The element boundary requires ClipToBounds=true throughout its contributing subtree in this increment; any false value bypasses, even if its current paint happens to fit. This conservative rule removes untracked overflow guesses.

Preparation suppresses all writes/notifications to live draw bookkeeping (notably RecentDrawWasClipped); it cannot alter input-visible state or invoke user public draw hooks. It uses the built-in paint body through an internal capture context, not a fake final Draw that mutates live observations. The last normal direct Draw is the sole authority for descendant clipping state. A cache hit requires exactly that observed generation/geometry and full containment of the capture rectangle in the inherited scissor. Under these restrictions each descendant's clipping flags are invariant. A changed/partial inherited clip, content generation, geometry, offset or support state first falls back to direct Draw, refreshing those flags before another candidate may be requested. No descendant replay or eligibility traversal is performed on a warm hit. MGTextBlock has another draw-produced input dependency: DrawSelf populates ActionBounds/ToolTipBounds, while UpdateSelf/TryGetToolTip consume or clear them. Therefore any text block with a parsed run whose HasAction or HasToolTip is true is explicitly unsupported for boundary capture in this increment. Maintain that classification when runs are parsed/replaced, not by scanning runs each frame. Inline formatting without actions/tooltips remains eligible. Such text and all enclosing boundaries draw directly every frame; a background-only cached brush on that text block may still qualify because its normal DrawSelf remains live. Do not claim the old direct-observation protocol preserves these consumable dictionaries. Keep the wrapper's ordinary base Draw bookkeeping. Public PropertyChanged remains available; redundant per-frame notifications caused solely by resetting clipped flags are not promised on skipped paint, while the resulting values and input decisions are preserved.

Public OnBeginDraw/OnEndingDraw/OnEndDraw subscriptions anywhere inside captured content disqualify it, including observation-only callbacks: they may draw, mutate, or rely on invocation frequency. Convert event backing to counted add/remove accessors without changing public event signatures. Built-in controls currently use these public events for their own painting (CheckBox, ComboBox arrow, Expander arrow, grids, OverlayHost, window decorations, context menus, ResizeGrip). Move those internal paint operations to explicit internal paint-stage hooks with tracked dependencies and the same order/clip; do not exempt a public subscriber by method-name inspection. Until migrated, those controls conservatively bypass. User handlers continue to execute once at their normal final Draw location; never during Prepare and never silently suppressed by a hit. The public wrapper's own callbacks are outside its content cache; changes they make before DrawContents invalidate the key immediately.

## Eligibility and composition decisions

| Case | Required behavior and validation |
| --- | --- |
| Default settings, unit transform/integer translation, stable content, full inherited-clip containment | Eligible after direct observation and a later Prepare. Verify native pixel parity and no target switches in final composition. |
| Layout UI scale (`MGScaleSettings` font/spacing/size/border/image, UIScaleMode) | Supported as resolved layout geometry, at actual pixel dimensions. Invalidate affected revisions after change; remeasure only through existing layout paths. Test each scale channel and override/inheritance. |
| Window.Scale not 1; active nonunit RenderScale; arbitrary rotation/shear/perspective/fractional translation | Bypass entire affected capture. Keep normal transform/scissor behavior. Even static nonunit scaling bypasses in this increment; no undersampled bitmap magnification. |
| Inherited clip fully contains capture rectangle | Eligible. Clip changes that still fully contain it need not rebuild if every other key is equal. |
| Partial intersection, fully outside, scissor disabled, unbounded descendant | Direct path; no new request. Verify no input-visible stale clipped flags on moving a panel into/out of a viewport. |
| Incoming effective opacity at boundary/brush other than exactly 1 | Bypass. Do not render children at opacity 1 then tint the flattened result: overlapping primitives would change per-primitive alpha semantics. Desktop opacity and ancestor opacity are included. |
| Descendant fractional opacity or translucent colors with boundary incoming opacity 1 | Bake original per-primitive alpha into transparent RGBA target, composite once with white tint/opacity 1 and premultiplied AlphaBlend. Preserve child order. Pixel comparison includes overlapping translucent children on opaque and transparent scene backgrounds. |
| Additive, Opaque, NonPremultiplied, depth tests, non-Deferred sort, wireframe, non-default sampler, caller effect | Bypass. Accept only canonical DrawSettings.Default semantics: AlphaBlend/Default alias, PointClamp, None/Default depth, SolidScissorTest, Deferred, no Effect. Descendant image sampling is allowed if audited and baked internally; caller settings are not guessed. |
| Custom element/brush | Unsupported by default. Explicit support promises deterministic bounded painting from tracked state only, no time reads/external mutable effects, no public callbacks/target switches, and correct invalidation for every change. Misdeclared support is caller contract violation; no automatic detection promised. |
| IsRenderVolatile=true anywhere contributing | Bypass ancestor boundary; keep normal updates and draw. Setting false re-evaluates maintained counters and permits a later observed candidate. Cached brushes also obey owner volatility. |
| Time-driven built-ins | Automatically contribute volatility while running/caret blinking/revealing/pulsing; user false cannot override built-in volatility. Paused/stopped state may become eligible. Value updates still invalidate even when volatile. |
| EffectFillBrush, image/nine-slice effect or ConfigureEffect, custom shader parameters | Unsupported under default Tracked discovery, including an apparently static Effect. An explicitly asserted CachedFillBrush source graph is the sole exception described below. MGImage effects remain unsupported inside a boundary. External Effect mutation/standard time parameters are not automatically tracked. |
| Nested RenderCache / CachedFillBrush inside a RenderCache | Outer capture paints descendants directly with all nested cache lookup/requests suppressed. Outer hit skips inner pixels. Inner direct draws may maintain their own entries on outer misses; no dependency on inner GPU contents, no cycles, no nested target switching. Revisions still propagate through both boundaries. |
| Window, tooltip, context-menu popup, modal/overlay desktop layer | Not flattenable as content. Their content may contain an explicit RenderCache; desktop/window ordering stays live. An ordinary sibling before/after a cache remains before/after it. |
| Removal/disable/disposal/budget pressure/allocation failure | Never show stale output; direct Draw and logical release followed by disposal at the next safe lifecycle/preparation point. Budget eviction may reduce hit rate, never correctness. |

## Explicit static brush source assertion

`SourceMode=Tracked` is the safe default and requires the known-source adapters or IMGRenderCacheSource contract. `SourceMode=ExplicitlyStatic` is a deliberate caller assertion over the entire wrapped brush graph, including custom resources, effects and ConfigureEffect callbacks. It enables the existing use case of a texture nine-slice plus a local/UV-only lighting nine-slice without pretending to infer shader behavior. It is not inferred from IsCacheEnabled, UseStandardParameters, an Effect name, a shader inspection or a prior unchanged frame.

The assertion promises that pixels are a deterministic bounded function of supplied local geometry, scale, UVs, textures, colors and explicitly managed parameters. The source must not depend on elapsed time, screen position, interaction state, arbitrary external state without invalidation, framebuffer contents, or previous draws. It must emit premultiplied output within supplied Bounds, avoid target switches and side effects, and restore temporary draw state normally. ConfigureEffect may only configure its effect from those declared inputs; it must not change UI state, counters, application state or invoke arbitrary observation callbacks. Standard parameters may be assigned by the existing binding, but a shader using time/screen-position/interaction parameters violates the assertion even if UseStandardParameters=true. The manager still applies ordinary opacity, clip, transform, lifetime, budget and observed-generation checks. Explicit owner/resource volatility always wins and causes bypass; ExplicitlyStatic cannot override it.

Known observable resource mutations still invalidate automatically. Caller-owned Effect parameter writes, texture uploads, raw collection mutations and other opaque changes require `cachedBrush.InvalidateVisual()` before the next Draw. There is no attempt to observe arbitrary Effect or shader state. Assertion-related unsupported-source counts are replaced by the wrapper's supported contract, while known volatility/geometry and source lifetimes are retained; default unsupported effects elsewhere in a containing panel still cause bypass. An outer RenderCache may flatten an ExplicitlyStatic brush directly during capture under this same assertion; it never needs an inner target. This avoids making nested-cache order determine eligibility.

A declaration such as `<CachedFillBrush SourceMode="ExplicitlyStatic">` around the existing layered nine-slice is the consumer migration path. Merely changing the XML namespace from the old game-local wrapper is insufficient because the new default is Tracked. Consumers must audit the lighting shader's dependency contract, add explicit invalidation wherever parameters/textures change, and call desktop.PrepareRenderCaches before scene drawing. This task changes no game code. Native acceptance compares a locally parameterized nine-slice effect source with its uncached original, tests SourceMode toggles and Copy, mutates effect parameters then explicitly invalidates, and confirms default Tracked and declared volatile sources bypass. A deliberately time-dependent shader without the required assertion stays live. Tests must not present a falsely asserted time-dependent source as supported correctness behavior.

## Brush/resource mutation policy

mgui-jpa.3.3 owns dependency adapters for known immutable/value brushes and additive IMGRenderCacheSource implementations on known mutable brush classes. Convert auto-properties such as MGBorderedFillBrush and MGPaddedFillBrush setters to notifying backing fields without changing their public types/signatures. Existing observable mutable brushes notify through explicit semantic setters; they do not acquire blanket NPC invalidation. No breaking additions to IFillBrush/IBorderBrush. A resource graph is discovered once on registration/replacement/explicit invalidation; subscriptions maintain its aggregate revision/support/volatility thereafter. Cycle detection at discovery rejects cyclic brush graphs. Owner detach removes subscriptions. CachedFillBrush.InvalidateVisual advances its own revision, reconciles the inner graph, and notifies all live registered owners. Owner.InvalidateVisual does the same for that owner's contributing resources; when a resource is shared, explicitly invalidate every owner or the common cached brush wrapper.

| --- | --- |

Disposed textures reject candidate. |

Failure example: uploading a new texture frame then invalidating after Draw is too late; invalidate before Draw or set IsRenderVolatile for the streaming owner. These are explicit responsibilities, not claims of transparent legacy observation.

Fixture interpretation matters: batched/layered each have 48 text cells (8×6); layered adds nine-slice and effect painting. The two scenarios have different pixels, so their difference is a workload-cost signal, not proof of an equivalent batching optimization. HUD has eight labels; animated-score changes one each Update. Scrolling has 60 rows; nested-clips has 60 inner scroll viewers, each with ten labels. A moving world is rendered in every workload. UI scale 1.5 changes layout through SetUniformUIScale; it is not Window.Scale and remains eligible under this contract.

These measurements support targeting stable layered decoration first: at 1080p/scale 1 it submits 193 calls and 162,888 managed bytes/frame versus 97 calls/70,728 bytes for simple cells. They also show why caching is selective: the HUD submits only about 0.105 ms, and nested-clips spends about 0.859 ms in Update/layout versus 0.362 ms submitting UI. A pixel cache cannot claim to remove that normal Update/input work. Present costs dominate several software-renderer workloads. The architectural choices therefore remain an explicit brush wrapper and explicit content boundary, constant-time idle checks, ordinary live siblings, and separate Prepare accounting.

For downstream comparisons use newly captured, matched normal and cache-disabled runs on the same source/build/backend, alternating variant order, with the same three-repeat/120-warmup/300-sample minimum and unchanged fixture state hashes. Do not compare hardware results directly against these llvmpipe milliseconds. Compute summed-phase metrics per raw sample before taking percentiles; summing individual phase medians is not a subtotal median. Report UpdateLayout, Prepare, WorldSubmission, UiSubmission and Present separately and their sum as an instrumented CPU/wall-phase subtotal. That sum excludes uninstrumented host/frame-loop work and is neither total wall-frame latency nor GPU time. Independently measure complete frame wall time if making a whole-frame claim.

Concrete timing gates account for the observed repeat spread rather than treating one run as noiseless. For a matched normal comparator and each workload/phase, let M be the median of its three run medians and R their max-minus-min spread. Disabled-cache and unsupported-fallback median regression must be no greater than `max(0.02 ms, 0.05*M, 2*R)` for UpdateLayout and UI-plus-Prepare separately. For p95 use the median of three run p95s and their spread, with `max(0.05 ms, 0.10*P95, 2*R95)`. This baseline has UI repeat-median spreads from 0.0028 to 0.2302 ms, so a universal 1% wall-clock claim would be unsupported. Report raw values and the threshold; a run within a wide noise band is inconclusive, not proof of zero overhead. Cache bookkeeping must add zero steady per-frame managed allocations when caching is unused; total measured allocation changes from unrelated batching work must be attributed separately.

For a claimed cache benefit on stable layered/cell fixtures, steady UI-plus-Prepare median must improve by at least 20% over the best equivalent normal/batching implementation and the absolute improvement must exceed twice the matched comparator's repeat-median spread. Its p95 must pass the nonregression gate above. No blanket speedup requirement applies to small HUD, partial clips, volatile content or continuously dirty boundaries; report where direct rendering wins and keep those live. Mixed-sibling tests must show no rebuilds of an unchanged static sibling over the measured interval; changed children inside a boundary must either cause observed-generation rebuilds or volatility bypass. Report amortization with `ceil(cold incremental preparation cost / warm per-frame saving)` when saving is positive, and mark it non-amortizing otherwise. Cold cost includes the initial normal draw and subsequent capture, not just texture creation. A negative/inconclusive comparison changes consumer recommendations, never relaxes correctness or makes caching automatic.

The comparison must run normal uncached rendering and normal batching improvements against explicit bitmap caching on the same fixtures: stable text/decorations, mixed animated siblings, changed child inside boundary, continuously dirty content, disabled-cache controls, scrolling/clipping and resize/reparent churn. Report warm hit cost, cold direct+prepare cost, hit/miss/rebuild/eviction counts, target bytes/entries and time to recover after a change. Include pre-scene Prepare in the measured rendering-phase subtotal; a faster final Draw alone does not establish a win. Caches remain opt-in regardless of outcome. A continuously dirty region should use volatility/live siblings; it must not claim speedup by excluding Prepare or input updates.

Fixed non-timing gates: zero cache-owned target allocations when unused; zero target switches attributable to caching in final composition; retained+in-flight bytes and entries always within configured limits; zero idle eligibility/discovery subtree visits after warmup; a changed generation must never composite stale pixels; no net GPU-resource growth across repeated equivalent create/remove/dispose cycles. The timing gates above govern downstream evaluation; claims require equivalent pixels, matched environment and complete phase accounting.
