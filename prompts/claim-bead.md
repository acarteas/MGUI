Claim the bead specified and implement it end-to-end.

Required workflow:

1.  Claim it.
2.  Read the bead fully, including description, design, acceptance criteria, dependencies, and comments.
3.  Implement the work.
4.  Keep the bead's notes updated using `bd note <ID> "..."` or `bd update <ID> --append-notes "..."`.

When adding notes, log only meaningful handoff information:

- important findings or root cause
- implementation decisions or tradeoffs
- blockers and how they were resolved
- important files, APIs, or behaviors changed
- remaining risks or follow-up work if anything is incomplete

Do not log every command, every file edit, or trivial status chatter.

Use concise notes in this style:

- Finding: ...
- Decision: ...
- Blocker: ...
- Change: ...
- Remaining: ...

When done, add a final note summarizing what changed. Do not close the bead until instructed to do so.
